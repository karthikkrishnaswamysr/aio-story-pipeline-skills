# Google Flow Stickman & Blocky Videos

## Use the attached Flow tab

Use **Browser Use exclusively** for all interaction with Flow, including reading the project, selecting references, entering prompts, submitting generations and reviewing clips. Work in the creator's existing, signed-in, attached Google Flow tab. Flow's Agent bar and standard prompt bar are two modes of the native project composer. Exclude the Flow MCP connector, APIs, AIO, Tool Builder and other custom tools. Enter the prompts yourself. If Browser Use loses the tab, pause and ask the creator to reconnect that same tab. Never switch to a new browser session or hand prompt entry to the creator.

Read [Operating the native project canvas](references/flow-operating.md) before interacting with Flow. Verify the visible project title and locate the native surface the task needs, either Characters in the left sidebar or the project composer. If the creator supplied a project link as well, match it to the attached project. If several tabs could match, ask which one. If sign-in is required, let the creator sign in and continue in the same tab.

## Pick up the brief

- **Character or voice only.** Follow [Characters and saved voices](references/characters-and-voices.md) to create a character or change the voice on an existing one. Report the name and voice visible on the reopened card. A request for character setup alone ends there.
- **Short pilot.** Use the supplied idea, length and twist. If the creator asks for a three-shot example, plan a setup, a change and a payoff with one visible action per shot.
- **Original film.** Use the creator's idea or script. If they request ideas, pitch five original choices with a first line, a visual moment and a twist. Ask only for missing decisions. Default to stickman, a two-minute story within the usual 1–3 minute range, 16:9 and one output per shot. Support 9:16, blocky avatars and shorter pilots when requested. Prefer Omni Flash 1.2 at 720p when the visible controls offer it. Confirm any material substitution.
- **Redo or resume.** Keep the existing approved plan and accepted takes. Locate the shot and its references in the same project, using the shot log and visible assets. For a requested change to S03, work on S03 only.

For an original story, follow [Story and shot design](references/story-and-shots.md). Choose [Stickman](references/style-stickman.md) or [Blocky](references/style-blocky.md). Use original characters and scenes, with a kid-safe tone by default. For an older audience, adjust the tone to the brief. Describe an unbranded look in plain visual terms. Make the shot list show the duration, camera, action, end state and exact audio for each shot. Show the story and shot plan for review unless the creator has already approved them or asked to skip that review. Approval of the plan covers creative decisions only. Use the separate credit approval for generation.

## Generate and review

1. Choose the requested input for generation. **Agent only** and **standard bar only** apply to image generation and retakes as well as video. With no preference, use Agent when visible and the standard bar otherwise. If the creator requests a different input for individual shots, follow the shot list for those shots. Use [Native prompt patterns](references/flow-agent-messages.md) for both inputs.
2. Choose references according to the speaking role. Use the saved Characters entry for an on-screen speaker. For a silent character under off-screen narration, use that character's approved portrait image as the visual ingredient and attach one separate narrator voice consistently across shots. A saved character's attached voice can encourage lip-sync. For narrated shots, use the Voiceover (V.O.) pattern: mouth hidden from the camera (profile, or three-quarter rear view when the character moves), no facial expression changes while the voice plays, line in a separate Audio section. Follow [Characters and saved voices](references/characters-and-voices.md) and [Native prompt patterns](references/flow-agent-messages.md). Preserve approved character and location references, wardrobe and distinctive items. Show newly created references for selection before video.
3. Before an action that can generate media, identify its scope and show the credit quote from the selected input. Wait for approval. Honor an explicit capped approval for the specified work. Images, variants and retakes count. Follow the accounting and recovery rules in the operating reference.
4. Generate one shot at a time by default. On a longer project, group shots only if the creator approves the group, its full price is visible, and the current Agent session has already demonstrated distinct, identifiable shot outputs. In the standard bar, use one shot per submission.
5. Confirm a playable video exists before opening, renaming or reviewing it. A progress percentage or generated title can also appear on a failed tile. Review the action, final state, mouth movement, prop connections, continuity and exact speech. Keep visual and audio verification separate. Preserve earlier takes and repair only the affected shot. After a second failed take, flag that shot for a decision while continuing other authorized work.
6. Record the shot, references, mode, take, visible tile, review decision, quoted credits and verified charges. For a story cut, follow [Native scene assembly](references/scene-assembly.md), assemble the selected takes, play the scene in order, and reopen it to verify the saved duration and clip count. If assembly is unavailable, play the clips in order and state the delivery format. Report pending review and audio limits. Download or publish only when requested.

## Narration timing and repairs

For a narrated story, present both routes from [Native prompt patterns](references/flow-agent-messages.md) ("Narrated films: choose the route") at plan time: silent shots plus a separately recorded voiceover (recommended for reliable narration), or narration inside Flow with the V.O. pattern and possible retakes. Record the creator's choice in the plan.


Show the actions and exact narration before generation when requested. Estimate a natural delivery before quoting credits. For calm narration of roughly 8–10 words, consider five or six seconds and check the selected model's available lengths. Allow more time for longer lines and pauses. Four seconds may require a shorter line. Follow [Story and shot design](references/story-and-shots.md) for timing and [Native prompt patterns](references/flow-agent-messages.md) for silent-character narration and clear physical actions.

When the creator authorizes more time, extend the affected shot and update the total duration and quote. Keep successful takes unless the requested change requires replacing them. A voice label verifies an assignment. Listening verifies the delivery, exact words and completion. If listening is unavailable, say so and keep audio timing unverified, including after a visual trim.
