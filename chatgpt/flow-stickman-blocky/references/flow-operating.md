# Operating the native Google Flow project

## Establish the target

Use Browser Use with the already-attached tab. Match the visible project title to the supplied or attached project. For character setup, locate Characters in the native project sidebar or the open Characters panel. For shots, locate the project canvas, its asset grid and its native prompt composer. Real project links can have different domains and an account segment in the path.

A custom tool, its editor or a builder chat has its own prompt field. From that view, return via the visible project navigation to the same project's native canvas before entering a prompt. If doing so could discard work, or the correct canvas is unclear, pause for the creator to bring the canvas into that same tab. Leave unrelated work, accounts and billing settings alone.

## Operate the selected input

| Input | Reference images | Video clips |
|---|---|---|
| Native Agent bar | Turn Agent on. Specify each requested image and the intended count. Match the images that actually appear to the list. | Attach or select the approved assets in the composer. Enter the direction for the specific shot, including its required end state. Inspect the proposed model, settings, count and cost where shown. |
| Native standard prompt bar | Turn Agent off. Choose Image and one output. Enter one complete reference description and its style. Repeat for the next reference, respecting its quote. | Choose Video and Ingredients, select the approved images from this project, enter one self-contained shot and verify model, aspect, resolution, duration and output count. Use Frames only when that technique is requested and the chosen controls support it. |

Identify controls by their currently visible labels. Check selected reference thumbnails in the composer before submitting. When Agent is optional and unavailable, use the visible standard bar in that same tab and report the route. If the creator expressly requires a particular mode and it is unavailable, pause. A request to use both modes deliberately is also an explicit mode choice.

## Credit approval

Choosing an existing voice and saving the character can proceed as requested when the visible controls only edit its details. Apply the normal quote and approval rules to character images and any voice preview or creation action that can spend credits.

Show the live quote for the exact request, including the number of outputs. On an Agent message, sending can itself start generation. Use its quote/confirmation preview only when the visible UI establishes that sending the draft will stop before paid generation. If sending could spend before a quote is available, leave it unsubmitted. Use the other permitted native input for the actual generation only if it shows its own quote and the creator's mode choice permits it. If neither permitted route exposes a quote, pause.

An approval for an individual request covers that request once. When the creator explicitly authorizes a scope up to a total, count completed charges and reserve the displayed cost of pending or unverified submissions. Keep each unresolved request at its full quoted cost in the remaining budget and avoid counting it twice when a charge is verified. Stop before the next quote would exceed the cap. A request to approve every generation still requires a decision for each one. Reconfirm if a quote increases or the scope changes. If a scope includes multiple images with no combined quote, price and submit them separately.

Keep the approval tied to its stated scope. A cap that explicitly includes duration adjustments or targeted repairs covers those actions while they fit the cap. Continue already-authorized shots without asking again. Preserve a successful take when repairing another shot. If the next action needs more credits, finish independent work covered by the existing approval and request the exact additional amount needed. Show both the added amount and the revised overall allowance.

Treat displayed prices and model durations as live values. Verify the human-readable seconds after changing a slider, since its numeric value can be an index. Recheck the quote after changing the length, resolution, output count or references.

For failed generations, distinguish a promised refund from a verified credit return or absence of a debit. Use the visible credit history or an isolated balance change when available. The linked credit-activity page can be inspected through the same connected browser for this task. Keep unrelated account settings alone. Retain the failed attempt in the log and report any remaining uncertainty.

## Review and recover

Compare the completed clip to its shot card and selected references. Fail a missing story action or wrong final state even if the image looks attractive. Check who speaks, the exact words, and any unwanted voice label when speech is part of the brief. If sound cannot be heard through Browser Use, mark audio unverified and ask the creator to check playback in the same tab. A grid thumbnail is sufficient to identify a take but cannot verify motion or audio.

Inspect the tile's current status after rendering. A title, absent percentage, or 100% indicator alone is insufficient. Confirm a playable video and then open it. A tile with **Failed**, a warning, **Retry**, or a refund notice is a failed attempt. Read its reason before choosing recovery.

Before renaming a shot, confirm the video editor is open using a visible editor-specific control such as **Done editing scene**. The project canvas also has an **Editable text** field. Match the heading and editing surface before filling that field so the project title stays correct.

Keep a small chat log. Use the visible tile title, or a distinguishing thumbnail and its position at the time of submission. Use an identifier only when the UI exposes it. Distinguish planned, pending, accepted, rejected and unresolved. A displayed price is a quote. Mark the charge verified only from attributable usage or an isolated balance change visible in that same tab. Otherwise leave it unverified.

If disconnected or submission is uncertain, pause. After the same tab is reattached, confirm its project, examine pending tiles and match completed outputs against the shot log. Continue from the first unfulfilled action. Never resubmit an unresolved attempt on a guessed timeout. If a failed or absent attempt is conclusively identified, report it and apply the normal quote and approval rules to any new attempt.

For a targeted redo, select the failed shot in the grid. Use its native edit control when available or compose a replacement for that shot with the same references and settings. Change the requested element, check the quote and review the new version. Keep both visible takes and the accepted choices for all other shots.

For a harmless scene rejected by a content filter, record the actual warning and make the intended action clearer. Describe the object, mechanism, hand positions and visible movement plainly. For example, show a brass railway bell swinging once while an observer's hands stay behind their back. Keep the story meaning and use the approved narration. Ask before changing a material story beat or its exact line. A clearer prompt can still be rejected, so verify the result. After two failed takes, flag the shot for a decision and continue other authorized work. Respect actual service restrictions.

Reuse approved references and settings through the native **Reuse prompt** control when helpful. Check the resulting ingredient types and prompt before submission. A reused saved Character may bring a voice assignment back into a silent-character shot.

## Speed of the run
Browser work is many small, observable steps. A maximum-effort reasoning setting adds long pauses before each click without improving the result. In TechGyro's run, GPT-6 Astra at Max was slow; GPT-6.1 Sol at High handled the whole production. If the creator asks why the run is slow, suggest a lower effort setting for the browser steps.
